## 불변 기준과 경계 제외

양성 각 SUCCEEDED(4), terminal qpos XY 오차 ≤.30 m, 전송부터 terminal까지
≤150 wall s다. 150은 G03 유지이며 음성의 동일 예산은 본 거부 시험의 사전 설계
선택이다. boundary도 같은 관측 예산을 사용한다. 전체 세션 outer budget은
7,200 wall s이며 이는 42×150에 startup/종료 여유 900을 더한 운영 상한이다.

G03 v3의 나머지 기준은 그대로다. 기립은 z≥.22 m·|roll/pitch|≤15°의 연속
1 sim s 끝이 시작 후 10 sim s 이내여야 한다. 이후 z<.18 m 또는 각도>60°인
fall frame 0, 비바닥 contact 0, 매 physics step clearance≥.10 m다.
G03의 동일 native posture·clearance·contact 코드를 그대로 사용한다.
G03 문서에 명시한 값의 출처도 그대로이며 실물 안전 경계로 일반화하지 않는다.

경계는 마지막 B01 전송 시각부터 physics 종료까지 별도 구간이다.
해당 구간의 도달·시간·오차·통로 coverage·contact·clearance·fall·recovery
성능은 기록만 하고 G04 verdict에서 제외한다. B01 전까지의 전체 기립·주행
physics는 모두 본 판정에 포함한다. 경계 실패를 본 시험 실패로 바꾸지 않는다.
경계도 안전 한계 위반 시 즉시 종료하며 미수행 경계는 명시한다.

명령 primary 전수 귀속과 map→odom owner, 계측 완전성, 종료는 경계를 포함한
전체 세션에서 확인한다. RMW handle→DDS GUID→실제 graph node이며
dds_take를 유지한다. 미식별·외부 메시지/endpoint 0, fallback 0이다.
서로 다른 Nav2 GID의 [t,t+.25 wall s) 창 중첩 0이며 zero Twist도 포함한다.
map→odom은 AMCL 하나, lifecycle 여섯 FINALIZED, SIGKILL·TERM/KILL
escalation·owned residue·cleanup error 0과 기존 process identity 보존을 요구한다.
physics·GT·동시각 AMCL·path·action result/status·command·owner·parameter dump가
빠지거나 instrument failure가 있으면 FAIL이다.

Recovery는 현재 구성 spin/backup/wait를 허용한다. 실제 status의 UUID·active
시작/terminal·시간·sender GUID/node·횟수를 남기고 각 active recovery는 terminal
4/5/6으로 끝나야 한다. 주행 구간 recovery 미종료는 FAIL이다. 발신자 overlap이나
미식별을 recovery라는 이유로 면제하지 않는다. 미관측 행동은 coverage 미검증이다.

## 실패 처리와 반복

일반 goal 실패는 재시도 없이 다음 사전 목표로 진행하고 FAIL을 보존한다.
timeout은 cancel 응답과 action terminal까지 각각 최대 10 s 안에 확인한다.
cancel/terminal 불완전·process/instrument 실패는 즉시 세션 종료 FAIL이다.
접촉·낙상·clearance<.10은 감지 즉시 안전 종료한다. 본 구간에서 발생하면
남은 목표 미실행과 함께 FAIL, 경계에서 발생하면 경계 관측 실패로 남긴다.

동일 기준·입력·구현·설정으로 fresh 세션 3회 순차 수행한다.
세션 1이 실패해도 2·3은 새 simulator/RL/AMCL로 각각 수행하며 대체 실행은 없다.
각 회의 모든 적용 gate PASS이고 세 회 모두 PASS일 때만 G04 PASS다.

PASS이면 PR을 병합하고 정확한 main CI success와 merge hash를 확인한다.

recovery·경보·teardown verdict를 추가한다.

### 도달 목표의 FREE 배치

도달을 요구하는 양성 34개와 경계 4개는 동결 global costmap에서 목표 중심이
속한 cell의 cost가 **0**이어야 한다. 의도적으로 막힌 목으로 보내는 음성
X01~X04는 v1의 blocked/no-path 거부 조건과 좌표를 유지한다.

근거는 v1 `run-1/goal29_global_costmap.json`의 실제 OccupancyGrid다. FREE cell
중 원래 map XY와 Euclidean 거리가 가장 가까운 cell 중심을 선택한다. yaw는
유지하고 고정 역변환으로 world XY를 계산한다. inscribed(cost 99) cell 중심까지
최소 거리에서 반 cell 대각선 `.05/sqrt(2)`를 뺀 보수적 영역 여유가 `.20 m`

### 경보·abort·teardown 전 안전 정지

경보 또는 세션 abort/정상 종료 시 먼저 Nav2 action 목표들에 cancel-all을
요청하고 즉시 기존 bridge command topic에 zero Twist를 발행한다.
zero를 50 Hz로 유지하면서 GT의 `.25 sim s` 차분 선속도 `<.03 m/s`와
각속도 `<.10 rad/s`가 연속 `1 sim s` 성립하는지 최대 `15 wall s` 확인한다.
확인 후에만 lifecycle teardown을 시작하며 zero는 teardown 중에도 유지한다.
확인 timeout·취소 미완료·표본 누락은 instrument FAIL이다.

새 정지 발행자는 실제 graph GID/node로 귀속하고, 정지 요청 뒤의 모든 6축
zero만 허용한다. 그 전의 명령·nonzero·미식별 sender는 기존 기준대로 FAIL이다.
서로 다른 Nav2 GID의 `.25 s` 중첩 기준도 그대로다. 정지 발행자 허용은
주행 명령의 외부 sender를 면제하는 규칙이 아니다.

경보 최초 native physics frame(일반 종료는 정지 요청 시각)부터 physics 종료까지
최대 GT XY 이동과 최소 clearance를 매 frame으로 기록한다. 새 적용 gate는
**최대 이동 ≤.10 m**, **최소 clearance ≥경보 시 clearance−.05 m**,
**teardown 시작 전 연속 정지 확인**, **zero 명령 귀속 완전성**이다.
경계에서도 이 정지 gate와 계측·종료 조건은 적용한다. 경계의 주행 성능
제외와 본 구간의 기존 clearance≥.10 m는 유지한다.

사전 강제 시험은 실제 Nav2 목표로 이동 중 경보를 발생시켰다.
`safety-probe/forced-alert-2/result.json`: NavigateToPose/FollowPath 각각 취소 1,
terminal CANCELED(5), zero 첫 발행 약 `3.23 ms`, sim `10.70~11.70` 정지 확인
뒤 teardown이다. 최대 이동 `.028971744 m`, clearance
`1.166786270 -> 1.146724020 m`로 두 상한을 만족했다. 여섯 FINALIZED·SIGINT만
사용·잔류 0이다. 첫 진단의 physics 옵션 누락은 `forced-alert/result.json`의
instrument FAIL로 보존하며 v2 세 실행 표본에 포함하지 않는다.
